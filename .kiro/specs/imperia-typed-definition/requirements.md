# Требования: типизированные параметры Империи (Task 4)

Источник: `.kiro/steering/roadmap.md`, Task 4; дефект «босс читает JSON в горячем цикле (`Run.Boss.cs`: `F(...)`, `Floats(...)`, `Raw[...]`)». Правила боя — `Research/FullGame/Mechanics.md` §7, данные — `Research/Json/survivors_enemies.json`, `enemies/imperia`.

## Требования

1. КОГДА `GameData` загружает определение врага с классом `CSurvivorsEnemyDefinition_ImperiaBoss`, СИСТЕМА ДОЛЖНА создать `ImperiaDef` и записать в него без округления все параметры боя из данных: ярость (`m_flInitialEnrageTime`, `m_flIncrementalEnrageTime`, `m_vecMandatoryEnrageHealthThresholds`), магические ракеты, метеоры (горящую землю), лучи и демонические порталы, включая `m_vecDemonPortalSpawners`.
2. КОГДА у определения Империи нет обязательного поля боя, СИСТЕМА ДОЛЖНА прервать загрузку с ошибкой, в которой названы враг и отсутствующие поля. Отсутствующее поле не заменяется нулём или числом из кода.
3. КОГДА враг не является Империей, СИСТЕМА ДОЛЖНА оставить `EnemyDef.Imperia` пустым (`null`).
4. КОГДА идёт бой с Империей, СИСТЕМА ДОЛЖНА брать параметры атак только из полей `ImperiaDef` и `Rules`, без обращения к `EnemyDef.Raw` и без разбора JSON.
5. КОГДА бой требует числа, которого нет в данных (темп атак, разброс ракет, время жизни снарядов, радиус телеграфа лучей, разброс метеоров, период урона горения, радиус появления у портала), СИСТЕМА ДОЛЖНА брать его из `Rules` с пометкой **Р** в комментарии и в `Mechanics.md` §7.
6. КОГДА бой идёт после прогрева, СИСТЕМА ДОЛЖНА выполнять 300 шагов симуляции (ракеты, метеоры, порог ярости, лучи, открытие портала) без выделения управляемой памяти. Исключение — шаг, который пишет новое сообщение `Diagnostics`.
7. СИСТЕМА ДОЛЖНА СОХРАНИТЬ поведение боя: все существующие тесты `BossTests` проходят без изменения ожидаемых значений; при тех же `Rules` по умолчанию числа боя совпадают с прежними.

## Критерии приёмки
- Новые тесты `ImperiaDefinitionIsReadFromData`, `MissingImperiaFieldFailsLoading`, `BossStepsDoNotAllocate` проходят.
- `Run.Boss.cs` не содержит `Raw`, `JArray`, `Newtonsoft`.
- Полный `dotnet test DotNet/ThornThrone.Simulation.Tests` зелёный.
- Smoke `-thornBoss` работает как раньше (проверяет проверяющий агент; Unity-слой не меняется).
