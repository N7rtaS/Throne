# Документ требований к исправлению

## Introduction

Нажатие рывка иногда не срабатывает. Представление вызывает `Run.Update(deltaTime, move, dash)` раз в кадр, а симуляция выполняет только целые шаги `Rules.Step` = 1/30 с. При 60 FPS примерно в каждом втором кадре накопленного времени не хватает на шаг, и `Update` возвращается без единого `Tick`. Флаг `dash` этого кадра нигде не сохраняется, поэтому нажатие пропадает. Кнопка рывка на телефоне (ТЗ_Мобильная_версия_v2.md §6) отвечает примерно на половину нажатий. Чем выше частота кадров относительно 30 Гц, тем чаще это происходит.

Исправление: запрос рывка буферизуется до ближайшего шага симуляции. На паузе и во время выбора улучшения запрос сбрасывается, потому что пауза и выбор останавливают все игровые таймеры (ТЗ_Мобильная_версия_v2.md §8) и сбрасывают удержания ввода (§6).

Буферизация ввода между кадром и фиксированным шагом относится к технической стороне мобильного представления. Игровое правило рывка (заряды, перезарядка, длительность, скорость из данных героя, Mechanics §3) не меняется, поэтому отдельная запись в `Differences.md` не требуется.

Обозначения:
- «кадр без шага» — вызов `Update`, после которого накопленного времени меньше `Rules.Step` и не выполнен ни один `Tick`;
- «запрос рывка» — `dash = true` в вызове `Update`;
- «ожидающий запрос» — запрос рывка, ещё не переданный ни в один `Tick`.

## Bug Analysis

### Current Behavior (Defect)

1.1 WHEN `Update` вызывается с `dash = true` и в этом вызове не выполняется ни одного `Tick` (накоплено меньше `Rules.Step`), THEN the system теряет запрос: следующий шаг выполняется с `dash = false`, событие `HeroDashed` не возникает, `DashCharges` не уменьшается

1.2 WHEN забег идёт с частотой кадров выше 30 FPS (например, 60 FPS, `deltaTime` = 1/60 с) и игрок нажимает рывок в случайном кадре, THEN the system пропускает нажатие примерно в половине кадров, хотя заряд рывка доступен

### Expected Behavior (Correct)

2.1 WHEN `Update` вызывается с `dash = true` и в этом вызове не выполняется ни одного `Tick`, THEN the system SHALL сохранить ожидающий запрос и передать его в первый `Tick`, выполненный в одном из следующих вызовов `Update`; при доступном заряде и `dashTimer <= 0` в этом шаге начинается рывок с событием `HeroDashed`

2.2 WHEN забег идёт с частотой кадров выше 30 FPS и игрок нажимает рывок в любом кадре при доступном заряде, THEN the system SHALL выполнить рывок не позднее ближайшего шага симуляции

2.3 WHEN ожидающий запрос передан в `Tick`, THEN the system SHALL считать его израсходованным независимо от того, начался ли рывок (нет заряда или рывок уже идёт); запрос не переносится на последующие шаги

2.4 WHEN несколько вызовов `Update` подряд с `dash = true` приходятся на кадры без шага, THEN the system SHALL объединить их в один ожидающий запрос и выполнить не больше одного рывка в ближайшем шаге

2.5 WHEN есть ожидающий запрос и `Paused` устанавливается в `true`, THEN the system SHALL сбросить запрос; после `Paused = false` следующий `Tick` выполняется без рывка, если в новом вызове `Update` не пришёл новый запрос

2.6 WHEN есть ожидающий запрос и открывается выбор улучшения (`Choosing` = `true`), THEN the system SHALL сбросить запрос; после выбора улучшения следующий `Tick` выполняется без рывка, если в новом вызове `Update` не пришёл новый запрос

2.7 WHEN `Update` вызывается с `dash = true`, пока симуляция остановлена (`CanSimulate = false`: пауза, выбор улучшения или конец забега), THEN the system SHALL не сохранять этот запрос

### Unchanged Behavior (Regression Prevention)

3.1 WHEN `Update` вызывается с `dash = true` и в этом вызове выполняется хотя бы один `Tick`, THEN the system SHALL CONTINUE TO передавать рывок только в первый `Tick` этого вызова, а остальные шаги выполнять с `dash = false`

3.2 WHEN запросов рывка нет, THEN the system SHALL CONTINUE TO выполнять шаги с `dash = false` и выдавать при одинаковом seed, данных и последовательности ввода тот же результат, что до исправления

3.3 WHEN шаг выполняется с запросом рывка, THEN the system SHALL CONTINUE TO применять прежние правила рывка: расход заряда, длительность `DashDuration`, скорость `DashSpeed`, перезарядка `DashCooldown`, число зарядов `NumDashes` из данных героя (Mechanics §3), направление по `Facing`, неуязвимость при `Rules.DashGrantsInvulnerability`

3.4 WHEN симуляция остановлена паузой, выбором улучшения или концом забега, THEN the system SHALL CONTINUE TO не выполнять шаги, обнулять накопитель времени и не догонять пропущенное время после возобновления

3.5 WHEN `deltaTime` превышает 8 шагов, THEN the system SHALL CONTINUE TO ограничивать накопитель значением `Rules.Step * 8`

3.6 WHEN выполняется `Update` с ожидающим запросом или без него, THEN the system SHALL CONTINUE TO не выделять управляемую память в горячем цикле

3.7 WHEN запускаются существующие тесты `dotnet test DotNet/ThornThrone.Simulation.Tests`, THEN the system SHALL CONTINUE TO проходить все 54 теста
