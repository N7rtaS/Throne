# Дизайн: Land Mine, Mortimer Kisses (Task 24)
## Архитектура
Все файлы симуляции — в `UnityProject/Assets/Game/Scripts/Simulation` (чистый C# 9, без движка). Регистрация — в `AbilityFactory`.
| Файл | Что делает |
|---|---|
| `World/Entities.cs` | Класс `GroundObject` (пул) и `enum GroundPhase { Arming, Armed, Triggered, Falling, Burning }`; события `GroundObjectSpawned`, `GroundObjectEnded` в `SimEventKind`. |
| `Abilities/Abilities.cs` | Интерфейс `IGroundObjectAbility { bool UpdateObject(Run run, GroundObject obj, float dt); }` (false — объект кончился); 2 строки в `factories`. |
| `Run.Ground.cs` (новый partial) | Пул: `GroundObjects`, `ActiveGroundObjects`, `SpawnGroundObject(OwnedPowerUp, Vec2)` (null при переполнении, диагностика `pool:ground` один раз), `RetireGroundObject`, `UpdateGroundObjects(dt)` — обход пула и вызов обработчика источника. |
| `Run.Events.cs` | Перегрузка `Emit(SimEventKind, GroundObject, Vec2, float)` с `Slot` и `SpawnId`. |
| `Run.cs` | 2 строки: создание пула в конструкторе (`Create(Rules.MaxGroundObjects, …)`), `UpdateGroundObjects(dt)` в `Tick` после `UpdateProjectiles`. |
| `Rules.cs` | `MaxGroundObjects = 256`. |
| `Abilities/LandMine.cs` (новый) | Установка мин по перезарядке; фазы мины: взвод → ожидание врага → отсчёт → взрыв или истечение. Буфер `CircleTargets` способности. |
| `Abilities/MortimerKisses.cs` (новый) | Залп по перезарядке; выбор цели через `RandomTargets` в кольце; фазы объекта: полёт → лужа с тиками. Буфер `CircleTargets` способности. |
| `Abilities/RandomTargets.cs` | Перегрузка `Collect(run, center, minRange, range, wanted)`: кандидаты с расстоянием в `[minRange, range]`. Прежний `Collect` вызывает её с `minRange` 0, поведение Annihilation не меняется. |
| `Stats/Attributes.cs` | Id `LifeTime`, `ArmingTime`, `TriggerTime`. |
`GroundObject`: `Slot`, `SpawnId`, `Active`, `Source` (`OwnedPowerUp`), `Phase`, `Position` (место мины или точка падения), `Origin` (откуда выпущен шар), `Radius`, `Age` (с создания), `Timer` (до следующего события фазы), `FlightTime`, `Life`, `TicksLeft`, `Interval` и снимок удара (`Damage`, `DamageType`, `DamageFlags`, `DamageSource`, свойство `Hit`, как у `Projectile`). Объект неподвижен, поэтому `PreviousPosition` и снимок в `FixedStep` не нужны: представление считает шар на дуге из `Origin`, `Position`, `Age`, `FlightTime` и `run.Alpha`.
Unity-слой (`Scripts/Mobile/WorldRenderer.cs`): каждый кадр обходит `run.GroundObjects` и рисует временные замены — мина (маленький тёмно-красный диск, ярче в фазе отсчёта), шар (оранжевая сфера на дуге), лужа (оранжевый полупрозрачный диск своего радиуса). Чистая функция `WorldRenderer.GlobPoint(origin, target, progress)` (дуга) проверяется EditMode-тестом. Вид не хранит состояния между кадрами по слоту, кроме случаев, где он сверяет `SpawnId`. Взрыв мины — существующий диск `AbilityBurst` (0.15 с). Smoke: общий `-thornForce` и `SmokeForce` без изменений. Отличия — `Differences.md` Б16.
## Данные
Числа — только из `survivors_powerups.json` через `Build.Stat`/`AbilityBase` (ранги со смещением §4). Поля вне атрибутов: `m_flMinRange` читается через `DataField` (отсутствие — диагностика `ability:mortimer_kisses:m_flMinRange`). `m_flLaunchDistance`, `m_flScepterLaunchDistance`, `m_flAnglePerShot`, `m_flSpawnPickupOnKillPercent`, `m_unSpawnPickupOnKillID`, `m_flScepterVacuum*` в этой задаче не используются (Р6, Р14, Task 27).
## Правила (метки для Mechanics §31)
Источники **Д** и **К** — в requirements.md. Ниже — проектные решения.
### Пул
- **Р1. Пул `GroundObject`.** Один пул на забег, 256 слотов, общий для мин и луж (и для будущих наземных объектов). Оценка по данным: Land Mine ранга 9 — перезарядка 2.4 с при жизни 20 с, ≤ 9 мин; с глобальным сокращением перезарядки до нижней границы 0.1 с (`AbilityBase.Cooldown`) — до 200. Mortimer Kisses ранга 9 у Dragonus — 6 шаров за 3 с, каждый живёт ≤ 0.84 с полёта + 2 с лужи, ≤ 12 объектов. 256 покрывает худший случай с запасом.
- **Р2. Переполнение.** Нет свободного слота — новый объект не создаётся (мина не ставится, шар не выпускается), перезарядка всё равно начинается, `pool:ground` сообщается один раз за забег, как `pool:projectiles`. Старые объекты не вытесняются: вытеснение меняло бы уже поставленные мины игрока. При данных не достижимо (Р1).
- **Р3. Обновление.** `UpdateGroundObjects` идёт в шаге после снарядов (сетка уже перестроена) и при упавшем герое (как снаряды, §25 Р8): мины и лужи продолжают действовать, новые не появляются, потому что способности не тикают. Пауза, выбор и конец забега останавливают шаг целиком.
### Land Mine
- **Р4. Установка.** По истёкшей перезарядке (допуск полшага, §30 Р9), без проверки врагов — описание «устанавливает под собой мину»; первая — сразу после получения. Место — положение героя в шаге установки (**Д** по описанию «at your position»).
- **Р5. Снимок.** Урон, радиус `Radius × (1 + AoEIncrease)`, `ArmingTime`, `TriggerTime`, `LifeTime` — на момент установки (как §26 Р4). `DurationExtension` не продлевает `LifeTime`: у Land Mine нет `DurationEffect` (§30 Р10).
- **Р6. Взвод.** Первые `ArmingTime` (0.7) с мина не реагирует. Имя атрибута — `ArmingTime`, описание — «after an arming period»; локализованное имя «Ускорение подготовки» на правило не влияет.
- **Р7. Срабатывание.** Взведённая мина каждый шаг проверяет, касается ли круг поражаемого врага её круга (`CircleTargets.Any`, §28 Р1). **Радиус срабатывания равен радиусу взрыва** (`Radius`): отдельного радиуса в данных нет. С первого касания идёт `TriggerTime` (0.85) с; отсчёт не прерывается, если враг ушёл.
- **Р8. Взрыв.** По истечении отсчёта — физический урон каждому поражаемому врагу, чей круг касается круга мины в этот момент, по одному разу; отталкивания нет (нет `KnockbackDistance`); `AbilityBurst` (центр мины, радиус, ID 18) до урона; мина убирается. Не снаряд: криты и бонусы снарядов не действуют, `BonusPhysicalDamage` действует (§24 Р1).
- **Р9. Истечение.** `LifeTime` (20) с отсчитывается от установки. Невзорвавшаяся мина без отсчёта по истечении исчезает без урона. Мина, уже начавшая отсчёт, взрывается, даже если `LifeTime` истекло за время отсчёта.
- **Р10. Наложение.** Мины не ограничены числом, кроме пула; несколько мин в одной точке взрываются независимо.
### Mortimer Kisses
- **Р11. Применение.** По истёкшей перезарядке (допуск полшага), если есть поражаемый враг на расстоянии `[m_flMinRange, Range]` = [300, 1000] от героя; иначе проверка в следующем шаге. Перезарядка стартует с началом залпа; новый залп не начинается, пока не выпущен последний шар текущего (как Knife Throw, §29 Р7).
- **Р12. Мёртвая зона `m_flMinRange`.** Враги ближе 300 к герою не выбираются целью (как минимальная дальность Mortimer Kisses в Dota 2). Лужа радиусом 300 вокруг цели на 300 всё же может задеть врагов рядом с героем. Альтернатива — см. «Вопросы владельцу», п. 1.
- **Р13. Залп и цели.** `TargetCount` шаров: первый — в шаге начала, следующие — через `max(шаг, ProjectileAttackInterval)` (0.2). Каждый шар в момент выпуска выбирает одного случайного врага в кольце от текущего положения героя (`RandomTargets`, один бросок `Rng.Next`, если кандидатов больше одного; §30 Р15); цели шаров залпа могут совпасть. Нет кандидата в момент выпуска — шар пропускается, залп идёт дальше. Шар летит в **положение цели в момент выпуска** (не самонаводится): враг может уйти из лужи.
- **Р14. Полёт.** Навесной: не сталкивается с врагами, не блокируется стенами и пропастями, урона в полёте нет. Время полёта — `max(шаг, |точка − герой| / ProjectileSpeed)`. `m_flLaunchDistance` (700), `m_flScepterLaunchDistance` (1000) и `m_flAnglePerShot` (35) на правила не влияют: их смысл не восстановлен (**К** — только имена в клиенте); дуга шара — только отображение.
- **Р15. Лужа.** В шаге падения шар становится лужей радиуса `Radius × (1 + AoEIncrease)` в той же точке и с тем же `SpawnId`. `DamageTicks` тиков: первый — через `InitialTickDelay` (в данных Mortimer нет — 0, тик в шаге падения), следующие — через `max(шаг, TimeBetweenTicks)`; после последнего тика лужа исчезает (при данных живёт 2 с). Каждый тик — магический урон каждому поражаемому врагу, чей круг касается лужи, по одному разу; отталкивания нет. Отдельного урона от удара шара нет: описание называет урон только у лужи. Не снаряд (`ProjectileAttack` нет): `Projectile_BonusMagicDamage` и криты снарядов не действуют.
- **Р16. Снимок.** Урон за тик, радиус, число тиков, задержка и интервал — на момент выпуска шара.
- **Р17. Наложение луж.** Несколько луж бьют независимо: враг в двух лужах получает тики обеих.
- **Р18. Событие.** Тики лужи событий `AbilityBurst` не дают (лужа и так видна); `GroundObjectSpawned` в момент выпуска несёт точку падения.
## Решения владельца (12.11.2026)
Владелец принял все предложенные варианты («дальше»):
1. **Р12 `m_flMinRange`** — вариант (а): враги ближе 300 к герою не выбираются; если все враги ближе 300, Mortimer Kisses ждёт. Отклонены (б) запасной выбор среди всех в `Range` и (в) отодвигание точки падения до 300.
2. **Р7** — радиус срабатывания мины равен радиусу взрыва.
3. **Р9** — мина без врагов исчезает через `LifeTime` (20 с) без взрыва.
4. **Р14** — `m_flLaunchDistance`, `m_flAnglePerShot`, `m_flScepterLaunchDistance` в правилах не используются.
5. **Р2** — при переполнении пула новые объекты не создаются, старые не вытесняются.
Решение по Swashbuckle (мировая ось ±X, §30 Р4) не меняется.
## Уточнения при реализации
- Объект не продвигается в шаге своего создания (поле `Born`): мина взводится через 21 шаг после шага установки, взрыв — через 26 шагов после касания; шар до цели на 800 летит 20 шагов, первый тик лужи — в шаге падения, следующие через 15 шагов.
- Объект, у способности которого нет обработчика (`OwnedPowerUp.Ability` снят), заканчивается сразу (Р3).
- Тест упавшего героя — на Dragonus (как `LivesTests`), жизнь добавляется после `ForceUpgrade`, который пересчитывает глобальные атрибуты.
## Тестовая стратегия
Фикстуры в `DotNet/ThornThrone.Simulation.Tests`: `GroundObjectPoolTests`, `LandMineTests`, `MortimerKissesTests`. Хелперы — `ChainBeamFreezeTests.Arena/Standing/Hits`, `RotTests.Upgrade/Base/Owned`, `EchoStrikeTests.Steps`. Ранги проверяются на Kez (у Dragonus врождённая даёт `TargetCount` +1 — проверяется отдельно). Ожидания — из данных (`RotTests.Base`) и таблицы рангов requirements.md.
- Реестр: `Run.IsImplemented` истинно, обработчик нужного типа, нет диагностик `ability:*` и `damage-type:*`; Land Mine — физический, Mortimer — магический.
- Ранги 1, 2, 3, 9 — по таблице.
- Пул: размер 256 по `Rules`; заполнение маленьким `Rules.MaxGroundObjects` → объект не создан, одна диагностика `pool:ground`, нет исключения; новый `SpawnId` при повторном использовании слота; `GroundObjectSpawned`/`Ended` несут слот и `SpawnId`.
- Land Mine: мины каждые 4 с под героем без врагов; враг у мины в 0.5 с — нет отсчёта, после 0.7 с — отсчёт; взрыв на шаге ⌈0.85 / шаг⌉ после касания; урон 30 всем касающимся, враг за радиусом не задет; враг ушёл во время отсчёта — взрыв всё равно, без урона ему; мина без врагов исчезает через 20 с без урона; один взрыв на мину; `AbilityBurst` на взрыв.
- Mortimer Kisses: враг на 200 — нет залпа, на 800 — есть, на 1100 — нет; время полёта до цели на 800 — 800 / 1200 с; нет урона в полёте даже по врагу на пути; 5 тиков по 6 через 0.5 с, первый в шаге падения; враг, вышедший из лужи, не получает следующий тик; ранг 2 — 2 шара через 0.2 с; две лужи на враге — тики обеих; разный выбор на seed 1–5 среди нескольких врагов, одинаковый на одном seed; `AnnihilationTests` без изменений.
- Общие: пауза и выбор не двигают перезарядки, отсчёты, полёт и тики; при упавшем герое мины не ставятся, лежащие взрываются; `StepsDoNotAllocateAfterWarmUp` с обеими; бот-забег Dragonus с обеими (120 с, seed 1–5) — обе бьют, новых диагностик нет (кроме известной `data:duplicate-attribute:knife_throw:ProjectileAttackInterval`).
- Инструменты: `Tools/tests/test_audit.py` — новые классы фабрики implemented; `python3 -m unittest discover -s Tools/tests`.
- Unity: EditMode `WorldRendererTests.GlobPointFollowsArcFromOriginToTarget`; обычный smoke и `Tools/mac-smoke.sh -thornForce=land_mine,mortimer_kisses`.
## Риски
- Две новые способности в выборе при уровне меняют выбор улучшений у забегов с прежними seed (как в Task 19–23); тесты, зависящие от точного выбора, на него уже не опираются.
- Перегрузка `RandomTargets.Collect` трогает Annihilation; защищена `AnnihilationTests` без изменения ожиданий.
- Новый пул добавляет обход 256 слотов за шаг и за кадр; стоимость мала по сравнению с пулом врагов (1024).
- Лужа нарисована похоже на горящую землю Империи (урон герою); цвет выбирается отличимым, финальный эффект — Task 37.
