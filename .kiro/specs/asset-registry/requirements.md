# Требования: реестр ресурсов `AssetRegistry.json` (Task 7)

Источники: `.kiro/steering/roadmap.md`, Task 7; `ТЗ_Мобильная_версия_v2.md` §3 (поля реестра: исходный путь, хеш, зависимости, инструмент, Unity GUID и выходной путь, статус проверки), §10 (граф ресурсов, статусы, ненулевой код, входные хеши). Решение владельца от 10.11.2026: объём по roadmap; треугольники — только справочные поля, без проверки бюджетов (бюджеты — блок F по замерам на устройстве); поле `referencedBy` не пишется. Ограничение владельца: каталоги Steam и Dota этот инструмент не читает и не меняет — все входы уже лежат в проекте.

## Термины
- **Исходный ресурс** — строка `NestOfThorns/manifest.tsv` (путь, размер, архив, CRC32, причина) или файл внутри карты `NestOfThorns/maps/scenes/crownfall/survivors_arena.vpk`.
- **Ссылка** — внешняя ссылка RERL скомпилированного файла (`Tools/vpk.py: external_references`), путь приводится к скомпилированному (`compiled_path`).
- **Корни сущности** — ресурсы, на которые прямо указывает определение (design §3).
- **Выход Unity** — файл в `UnityProject/Assets/Game/Art/Converted/` (кроме `.meta`) и его `.meta`.
- **Обязательная сущность** — запись `ContentRegistry.json` с `required: true`, `reachable: true` и категорией `heroes`, `enemies`, `powerups` (роли `active-ability`, `passive-item`, `recipe`, `innate`), `pickups`, `levels` (решение **Р2**).

## Т1. Граф и записи
1.1. КОГДА запускается `python3 Tools/asset-registry.py`, СИСТЕМА ДОЛЖНА создать запись для каждой строки манифеста и каждого файла карты с полями `kind`, `crc32`, `bytes`, `archive`, `reason`, `references`, `usedBy`, `outputs`, `status`, `verification`.
1.2. СИСТЕМА ДОЛЖНА строить рёбра по RERL файлов в `NestOfThorns/` (определения → vmdl/vpcf/vsnd → vmat → vtex и далее транзитивно); запись карты VPK ссылается на все свои файлы.
1.3. ЕСЛИ файла из манифеста нет в `NestOfThorns/` или его CRC32 не совпадает с манифестом (для файлов карты — с CRC внутри VPK), ТО СИСТЕМА ДОЛЖНА завершиться с кодом 1, вывести список и ничего не записывать.
1.4. ЕСЛИ ссылка или корень указывает на ресурс, которого нет ни в манифесте, ни в карте, ТО СИСТЕМА ДОЛЖНА записать её в `summary.unresolved` (ссылающийся файл или сущность → цели); это не ошибка.
1.5. Поле `usedBy` СИСТЕМА ДОЛЖНА заполнить ключами всех сущностей `ContentRegistry.json`, из корней которых запись достижима.

## Т2. Выходы Unity
2.1. СИСТЕМА ДОЛЖНА связать выходы с источниками: `X.glb` и `X_physics.glb` → `X.vmdl_c`; `world.glb` → `world.vwrld_c` карты; PNG → `vtex_c` с тем же именем (без суффиксов `_orm_<n>` и граней куба); `materials/<имя>.mat` → `vmat_c` с этим именем; `Baked/<имя>.asset` → источник glb этого имени из `enemies.json`; `Arena/tile_*.tga` → `world.vwrld_c`.
2.2. Для каждого выхода СИСТЕМА ДОЛЖНА записать `path` (от `Assets/`), `guid` из `.meta`, `importer` (первый ключ `.meta`; для glTFast — `ScriptedImporter:glTFast`), `tool`, `stage` (`converted` или `baked`).
2.3. Для текстур СИСТЕМА ДОЛЖНА записать сжатие по платформам `DefaultTexturePlatform`, `Standalone`, `Android`: `maxTextureSize`, `textureFormat` (имя по коду, например 51 → `ASTC_8x8`, −1 → `Automatic`), `textureCompression` (имя).
2.4. Для glb СИСТЕМА ДОЛЖНА записать справочные `triangles` (все меши) и `visibleTriangles` (стиль 0: без `_dummy` и `_style`) — без сравнения с бюджетами.
2.5. ЕСЛИ у выхода нет `.meta` или в нём нет `guid`, ТО СИСТЕМА ДОЛЖНА завершиться с кодом 1.
2.6. Выходы, не связанные ни с одним источником, СИСТЕМА ДОЛЖНА перечислить в `summary.orphanOutputs` (отчёт, не ошибка).

## Т3. Статусы
3.1. Статус записи — `converted` (есть выход стадии `converted`), `baked` (есть выход стадии `baked`), `recreated` (заменён ассетом проекта по переопределениям), `none` (достижим из обязательной сущности, выхода нет), `unused` (не достижим ни из одной обязательной сущности или помечен в переопределениях с причиной).
3.2. `verification` — `unverified`, кроме записей с полем `verified` (ссылка на документ проверки) в переопределениях — тогда `verified`.
3.3. ЕСЛИ переопределение относится к неизвестному источнику, имеет статус не из `recreated`/`unused`, `unused` без `reason` или `recreated` без `unity`, ТО СИСТЕМА ДОЛЖНА завершиться с кодом 1.

## Т4. Справочный раздел моделей
4.1. СИСТЕМА ДОЛЖНА записать в `models` вид каждой модельной сущности: для `looks.json` (герои и враги с моделью героя) — тело и предметы с её стилем, сумма видимых треугольников; для `enemies.json` — модели врага, максимум (враг рисуется одной моделью). Стиль N без своих мешей откатывается к стилю 0 (как `HeroView`).
4.2. СИСТЕМА ДОЛЖНА вывести таблицу Markdown «сущность | роль | модели | видимые треугольники». Бюджеты не проверяются, код выхода от треугольников не зависит.

## Т5. Обязательные сущности
5.1. Для каждой обязательной сущности СИСТЕМА ДОЛЖНА проверить, что хотя бы одна запись реестра её использует (`usedBy`).
5.2. Сущности без записей СИСТЕМА ДОЛЖНА перечислить в `summary.missingRequired` и вывести их число; код выхода не меняется (**Р5**).

## Т6. Воспроизводимость
6.1. СИСТЕМА ДОЛЖНА записать `Research/FullGame/AssetRegistry.json` с отсортированными ключами, без времени запуска, через временный файл; повторный запуск на тех же входах даёт побайтово тот же файл.
6.2. СИСТЕМА ДОЛЖНА записать в `inputs` SHA-256 входных JSON и манифеста и версию Source2Viewer из `SourceVersions.json`.
6.3. СИСТЕМА НЕ ДОЛЖНА читать каталоги Steam/Dota и запускать внешние программы.
6.4. `--out DIR` задаёт каталог вывода, `--root DIR` — корень проекта (для тестов).

## Коды выхода
0 — успех; 1 — нарушение входов (нет файла, CRC32, `.meta`, неверное переопределение).

## Критерии приёмки
- `python3 -m unittest discover -s Tools/tests` зелёный, включая `test_asset_registry.py`.
- На реальных данных скрипт завершается с кодом 0; `skywrath_mage.vmdl_c` связан с `skywrath_mage.glb` (GUID `9ba625c5010514a5b96c0e165405d258`); у Dragonus, Империи и врагов `enemies.json` есть справочный вид; у каждой обязательной сущности вне `missingRequired` есть запись.
- `AssetRegistry.json` создан, повторный запуск не меняет файл.
- `dotnet test DotNet/ThornThrone.Simulation.Tests` зелёный (симуляция не меняется).
- `Tools/README.md` описывает шаг; ТЗ §2 и §13 больше не говорят, что реестра нет.
