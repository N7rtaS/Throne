# Требования: исследовательский инструмент Dota, только чтение (Task 6)
Источник: `.kiro/steering/roadmap.md`, Task 6. Решение владельца: новых наблюдений в клиенте не будет, неизвестные правила ищутся в установленной Dota 2 строго только чтением (`product.md`, «Исследование оригинала»). Порядок поиска ответа: `Research/Json` → `Mechanics.md` → локализация и описания → panorama → строки бинарников `bin/osx64` → вики. Контракт инструментов: `ТЗ_Мобильная_версия_v2.md` §10 (ненулевой код при ошибке, входные хеши, отчёт), §3 (имя класса или поля не доказывает алгоритм, метка **К**).

## Термины
- **Каталог Dota** — `--dota`, иначе `THORN_DOTA_DIR`, иначе `~/Library/Application Support/Steam/steamapps/common/dota 2 beta/game/dota`.
- **Запретная зона** (решение владельца 10.11.2026: «весь Steam не редактируй, можно только читать и извлекать») — объединение корней, сравнение по `os.path.realpath`:
  - известный каталог Steam `~/Library/Application Support/Steam`;
  - корень библиотеки Steam, в которой лежит Dota: родитель ближайшего к Dota компонента пути `steamapps` (для внешней библиотеки `/Volumes/X/SteamLibrary/steamapps/…` это `/Volumes/X/SteamLibrary`);
  - если в пути Dota нет `steamapps` (нестандартная установка), — корень установки: родитель `game`, если каталог Dota лежит в `game`, иначе сам каталог Dota.
- **Проверяемый каталог** — корень установки Dota (`…/dota 2 beta`, родитель `game`; без `game` — сам каталог Dota). Его снимок сравнивается в `--check-readonly`.
- **Бинарники** — `bin/osx64/libclient.dylib` и `bin/osx64/libserver.dylib` каталога Dota.
- **Поля данных** — все ключи `m_*` в `Research/Json/survivors_*.json`.
- **Читаемое поле** — поле, имя которого стоит строковым литералом `"m_…"` в `UnityProject/Assets/Game/Scripts/Simulation/**/*.cs`.
- **Powerup** — запись `Research/Json/survivors_powerups.json` с `_class` (47 записей).

## Требования
### Т1. Только чтение
1.1. СИСТЕМА ДОЛЖНА открывать файлы в запретной зоне только в режиме `"rb"` через одну функцию; любая попытка открыть их в другом режиме ДОЛЖНА завершать работу с ошибкой до открытия.
1.2. ЕСЛИ любой выходной путь (включая `--out`) после `realpath` лежит в запретной зоне, ТО СИСТЕМА ДОЛЖНА завершиться с кодом 3 до чтения входов и ничего не записать.
1.2а. ЕСЛИ каталог проекта лежит в запретной зоне (например, при нестандартном `--dota` корень библиотеки накрывает проект), ТО СИСТЕМА ДОЛЖНА завершиться с кодом 3 до чтения входов и ничего не записать.
1.3. СИСТЕМА НЕ ДОЛЖНА запускать внешние программы с входными или выходными путями в запретной зоне. Source2Viewer получает на вход только копии из `NestOfThorns/`.
1.4. КОГДА задан `--check-readonly`, СИСТЕМА ДОЛЖНА снять список файлов проверяемого каталога (путь, размер, `st_mtime_ns`) до и после работы; ЕСЛИ появился, исчез или изменился хотя бы один файл, ТО СИСТЕМА ДОЛЖНА вывести список и завершиться с кодом 4.

### Т2. Строки бинарников
2.1. КОГДА запускается инструмент, СИСТЕМА ДОЛЖНА извлечь из каждого бинарника строки печатных ASCII-символов длиной от 4 и записать `Research/Decoded/client/strings.json`.
2.2. В файле ДОЛЖНЫ быть разделы:
- `survivors` — все строки, содержащие `survivors` без учёта регистра, по бинарникам;
- `classes` — имена классов `CSurvivors*`, `CDOTA_Survivors*`, `ISurvivors*` без префикса длины манглинга;
- `enums` — значения `k_eSurvivors*`;
- `dataFields` — каждое поле данных с признаками `inClient` (есть в бинарниках) и `readBySimulation`;
- `unreadFields` — поля данных с `readBySimulation = false`;
- `clientOnlyFields` — строки `m_*` в окрестности строк `survivors` (правило в `design.md` §3.2), которых нет в данных; отдельно подсписок `m_fl*`. Помечены как кандидаты (**К** не доказывает принадлежность режиму).
2.3. Каждый список ДОЛЖЕН быть отсортирован и без повторов.

### Т3. Локализация Panorama и тексты меню
3.1. СИСТЕМА ДОЛЖНА прочитать `resource/localization/dota_english.txt` и `dota_russian.txt` из `pak01_dir.vpk` (через `Tools/vpk.py`, проверка CRC32) и записать `Research/Decoded/panorama/localization_english.json` и `localization_russian.json`: ключи `DOTA_Survivors_*`, ключи с `Survivors` или `NestOfThorns`, ключи `#…`, на которые ссылаются декодированные разметки режима и строки `survivors` бинарников.
3.2. СИСТЕМА ДОЛЖНА декодировать Source2Viewer все файлы `panorama/layout/**` и `panorama/styles/**` из `NestOfThorns/manifest.tsv` в `Research/Decoded/panorama/` с теми же относительными путями (без суффикса `_c`).
3.3. ЕСЛИ копия в `NestOfThorns/` отсутствует или её CRC32 не совпадает с записью в VPK Dota, ТО СИСТЕМА ДОЛЖНА завершиться с кодом 1 и подсказкой запустить `extract-resources.py`.
3.4. СИСТЕМА ДОЛЖНА записать `Research/Decoded/panorama/menu_texts.md`: для каждой разметки — ключи `#…` с английским и русским текстом и литеральные тексты `text="…"`; ключ без перевода помечается «нет в локализации».

### Т4. Описания powerups
4.1. СИСТЕМА ДОЛЖНА записать `Research/FullGame/Descriptions.md` с описанием всех 47 powerups, сгруппированных по роли (`audit.powerup_role`): 17 активных, 16 пассивных, 9 рецептов, 3 врождённых, 2 служебных.
4.2. Для каждой записи СИСТЕМА ДОЛЖНА вывести: ключ, `m_unPowerUpID`, класс, рус./англ. имя, описание, героя-источник и описание Aghanim (поля `m_sLoc*`), базовые атрибуты (`m_vecBaseAttributes`), атрибуты подсказки (`m_vecTooltipAttributes`) с рус. именами атрибутов, глобальные атрибуты пассивок и рецептов (`m_vecGlobalUpgradeAttributes` малых улучшений), состав рецепта, максимальный ранг.
4.3. Плейсхолдеры вида `{f:0:counter_chance}` СИСТЕМА ДОЛЖНА оставить как в оригинале и перечислить под текстом с пометкой «значение подставляет клиент».
4.4. ЕСЛИ поле `m_sLoc*` ссылается на ключ, которого нет в локализации, или число powerups не 47, ТО СИСТЕМА ДОЛЖНА завершиться с кодом 2 и перечислить нарушения. Отсутствующее поле `m_sLoc*` не ошибка: строка «нет в данных».

### Т5. Воспроизводимость и отчёт
5.1. КОГДА инструмент запускается повторно на тех же входах, СИСТЕМА ДОЛЖНА записать побайтно те же файлы (без времени запуска, сортировка, `\n`, UTF-8).
5.2. СИСТЕМА ДОЛЖНА записать `Research/research-client-report.json`: входы (путь относительно каталога Dota или проекта, размер, SHA-256), версия клиента из `steam.inf`, если он есть, иначе из `Research/FullGame/SourceVersions.json`, версия Source2Viewer, число записей в каждом выходе.
5.3. Коды выхода: 0 — успех; 1 — нет входа; 2 — нарушение данных (Т4.4); 3 — выход или проект в запретной зоне; 4 — проверяемый каталог изменился.
5.4. СИСТЕМА ДОЛЖНА использовать только стандартную библиотеку Python 3 и Source2Viewer CLI (`THORN_S2V_CLI`).

### Т6. Ответы из клиента
6.1. После запуска инструмента в `Mechanics.md` ДОЛЖЕН появиться раздел «Ответы из клиента» по каждому открытому вопросу §12 (3–7, 9, 10): что найдено, где (файл и ключ или строка), метка (**Д**, **К**, **Р**) или «не найдено». Найденная строка без алгоритма — **К**, не **Н**.
6.2. `Tools/README.md` ДОЛЖЕН описывать запуск, выходы, коды выхода и гарантию только чтения.

## Критерии приёмки
- `python3 Tools/research-client.py --check-readonly` завершается с кодом 0; повторный запуск не меняет ни одного выходного файла (`git status` чистый после второго запуска).
- `Research/FullGame/Descriptions.md` содержит 47 записей, в том числе 17 активных способностей с рус. и англ. описанием.
- `python3 Tools/research-client.py --out <путь внутри Dota>` и `--out <путь внутри Steam вне Dota>` завершаются с кодом 3, в Steam ничего не появилось.
- `python3 -m unittest discover -s Tools/tests` зелёный; `dotnet test DotNet/ThornThrone.Simulation.Tests` зелёный (симуляция не меняется).
- В `Mechanics.md` есть раздел «Ответы из клиента».
