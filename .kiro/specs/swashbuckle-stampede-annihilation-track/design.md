## Архитектура
Все файлы — в `UnityProject/Assets/Game/Scripts/Simulation` (чистый C# 9, без движка). Регистрация — в `AbilityFactory`.

Отображение не меняется: удары Swashbuckle рисуются существующим прямоугольником `AbilityStrike`, начало набега Stampede и попадания Annihilation и Track — существующим диском `AbilityBurst` (0.15 с, пул 32 диска, лишние не рисуются), `-thornForce` и код 14 в `mac-smoke.sh` общие. Ускорение героя видно по движению; неуязвимость и метка Track на экране не показываются (Task 37). Отличия — `Differences.md` Б15.

## Данные
Числа — только из `survivors_powerups.json` через `Build.Stat`/`AbilityBase` (ранги со смещением §4). Полей вне атрибутов эти обработчики не читают. `m_flWarmupEffectTime`, `m_flMovementSpeedPercentDamageMultiplier` и тексты Aghanim в этой задаче не используются.

## Правила (метки для Mechanics §30)
Источники **Д** и **К** — в requirements.md. Ниже — проектные решения.

### Общее
- **Р1. Предупреждение** `m_flWarmupEffectTime` (Stampede 1.3, Annihilation 2) — только визуальный эффект, на время действия не влияет (как §26 Р8). Отображение — Task 37.
- **Р2. Время.** Перезарядки, серии и набег идут в шаге способности или героя: пауза, выбор улучшения и конец забега их останавливают. Падение героя во время набега невозможно (герой неуязвим); перезарядки при падении стоят (§25 Р8).
- **Р3. Тип урона** у всех четырёх — физический (`Damage_Physical`). Annihilation и Track — `ProjectileAttack` 1: действуют криты снарядов; бонус `Projectile_BonusMagicDamage` не действует (урон физический), `BonusPhysicalDamage` действует (§24 Р1). Swashbuckle и Stampede — не снаряды.

### Swashbuckle
- **Р4. Направления** (решение владельца 12.11.2026). `Directions` k направлений, равномерно по кругу, начиная с мировой оси +X (`Swashbuckle.BaseAxis`): k = 2 — +X и −X. Направление героя (`Facing`) не влияет. k = 4 (Aghanim, Task 27) даст и перпендикулярную ось без нового кода. Проверка при реализации: камера по данным (`m_vCameraOffset` 3300, −3300, 6600) повёрнута на 45°, поэтому мировая ось X на экране идёт по диагонали (вправо-вниз и влево-вверх), а горизонталь экрана — мировая (1, 1)/√2. Предположение спека «мировая X = горизонталь экрана» неверно; реализована утверждённая мировая ось, смена на экранную — одна константа `BaseAxis`.
- **Р5. Прямоугольник** — §26 Р2 от **текущего** положения героя на каждом ударе (`PLAYER_ORIGIN`; серия короткая, 0.18 с между ударами, герой «совершает удары» сам). Длина и ширина × `(1 + AoEIncrease)`; урон и отталкивание — снимок при начале серии.
- **Р6. Применение.** Как Echo Strike (§26 Р1): по истёкшей перезарядке, только если враг касается хотя бы одного прямоугольника; иначе проверка в следующем шаге. Перезарядка стартует с началом серии. Новая серия не начинается, пока не нанесён последний удар текущей (очереди нет): при данных серия длится не больше 5 × 0.18 = 0.9 с при перезарядке 1.6.
- **Р7. Удар.** Первый — в шаге начала серии, следующие — через `max(шаг, TimeBetweenTicks)`. На каждом ударе каждый враг получает урон не больше одного раза (враг на стыке двух прямоугольников — один удар, отталкивание по первому направлению). Отталкивание вдоль направления прямоугольника на `KnockbackDistance` (§25 Р4), после урона, только у выжившего врага с тем же `SpawnId` (§26 Р6).
- **Р8. Событие.** На каждом ударе одно `AbilityStrike` на направление: центр прямоугольника, направление, `Extent` = (длина, ширина), `Value` — ID 120.

### Stampede
- **Р9. Применение** (утверждено владельцем 12.11.2026). По истёкшей перезарядке, без проверки врагов (усиление героя; описание не требует цели); первое — сразу после получения, как у остальных способностей. Перезарядка 30 с стартует с началом набега. Перезарядки Swashbuckle, Stampede и Track считаются истёкшими, когда осталось не больше половины шага: 900 шагов по 1/30 с в float оставляют от 30 с ≈ 1·10⁻⁴ с, и без допуска набег запаздывал бы на шаг. `InstantAttack` (Kez, Annihilation) сохраняет прежнюю проверку `> 0`, второй удар Annihilation приходит на шаг 1802 вместо 1801. Smoke `-thornForce` ждёт попаданий каждой принудительной способности до 65 с игрового времени (`SmokeForce.MaxSeconds`): первый набег на 0 с проходит без врагов, второй — на 30.03 с.
- **Р10. Длительность** набега — `Duration + DurationExtension`. Предложение: `DurationExtension` («Доп. длительность эффектов», Timeless Relic) продлевает и собственную длительность Stampede. Довод: `DurationEffect` 1 стоит именно у способностей с длительностями (Magic Missile, Chain Frost, Frostbite, Track, Stampede, Spirits, Snotty Bat), это похоже на признак «длительности продлеваются». Закрывает §25 Р5 для Stampede (Spirits — Task 25). **Утверждено владельцем 12.11.2026.**
- **Р11. Скорость.** Во время набега герой идёт со скоростью `max(MovementSpeed, StampedeMovementSpeed)` (700 вместо 280) по вводу игрока; сам по прямой не бежит (сенсорное управление, игрок держит направление). Рывок действует как раньше со своей скоростью. Если набег начат во время текущего (невозможно при данных), остаётся большая скорость и большее оставшееся время.
- **Р12. Неуязвимость.** Во время набега `DamageHero` не снимает здоровье ни от касания, ни от атак, снарядов и зон врагов и Империи; отражения нет (урон не получен, §24 Р6). Таймер касания идёт как раньше.
- **Р13. Удары.** Каждый шаг набега враги, чей круг касается круга `Radius × (1 + AoEIncrease)` вокруг героя (`CircleTargets`, §28 Р1), получают физический урон, но каждый враг (`SpawnId`) — не больше одного раза за набег; затем отталкивание от героя на `KnockbackDistance` (30). Учёт — массив по слотам пула (номер набега и `SpawnId`), без выделений. Интервала в данных нет, поэтому одного удара на врага хватает «растоптать»; при скорости 700 герой проходит сквозь толпу.
- **Р14. Событие.** `AbilityBurst` в начале набега: положение героя, радиус круга, `Value` — ID 130.

### Annihilation
- **Р15. Наведение `RANDOM_TARGET_IN_RANGE`.** `TargetCount` разных случайных поражаемых врагов в `Range` от героя (Т2, `RandomTargets`). Если врагов не больше `TargetCount` — все, без бросков `Rng`. Иначе `TargetCount` бросков `Rng.Next` (порядок кандидатов — порядок запроса к сетке, он детерминирован).
- **Р16. Применение и удар.** По истёкшей перезарядке, если в `Range` есть враг (§26 Р1); удар мгновенный, в шаге применения, только по целям (радиуса нет). Порядок — как у `InstantAttack` (§26 Р13). Предел целей — размер пула врагов (ранг 9 — 250).
- **Р17. Событие.** На каждую цель `AbilityBurst`: положение цели, радиус `InstantAttack.BurstRadius` = 80 (только отображение), `Value` — ID 102. Выдаётся до урона.

### Track
- **Р18. Мгновенный удар.** У Track нет `ProjectileSpeed`, поэтому снаряд не летит (как Frostbite, §29 Р22): в шаге применения `TargetCount` самых сильных разных врагов в `Range` (§29 Р1) получают физический удар снарядом, затем, если живы и тот же `SpawnId`, метку. Без цели — проверка в следующем шаге. Цель выбирается без учёта уже наложенной метки: самый сильный может получить метку повторно (продление по §24 Р12).
- **Р19. Метка** — существующее усиление `Run.Amplify(сила IncomingDamageAmplification, длительность IncomingDamageAmplificationDuration + DurationExtension)`: весь не чистый урон по врагу × `(1 + сила)` (§24 Р4), наложение — большая сила и большая длительность (§24 Р12), от сопротивления статусам не зависит (Империя тоже помечается). Удар самого Track наносится до метки и не усиливается своей меткой. «Помечен» = `AmplifyTime > 0`; в данных усиление накладывает только Track.
- **Р20. Золото за помеченного.** Чисел в данных нет («выше шанс получить золото»). Предложение: если умирает помеченный враг, у которого есть награды (§25 Р11), бросок удачи для него заменяется гарантированным выпадением `m_luckyLootTable` (шанс 1 вместо `Luck` 0.05): монета ×1–3 и с шансом 0.2 ещё монета ×1–3 и мешок ×1–2, в среднем около 5.4 золота. Враги без наград (Империя, призванные, части големов) ничего не получают. Бросков `Rng` для шанса нет; `DropCollections` бросает как раньше. **Утверждён владельцем 12.11.2026 вариант (а).**
- **Р21. Событие.** На каждую цель `AbilityBurst`: положение цели, радиус 80, `Value` — ID 21.

## Решения владельца (12.11.2026)
Ответ «дальше» на вопросы спека: все предложенные варианты приняты.
1. **Р20** — вариант (а): помеченный Track враг с наградами всегда бросает `m_luckyLootTable` вместо броска удачи (≈5.4 золота за убийство). Варианты (б) второй бросок удачи и (в) шанс × (1 + усиление) отклонены.
2. **Р10** — `DurationExtension` продлевает набег Stampede.
3. **Р4** — Swashbuckle бьёт по мировой горизонтали (оси ±X), направление героя не влияет. Уточнение при реализации: на экране это диагональ 45° (см. Р4); если нужна горизонталь экрана, меняется `Swashbuckle.BaseAxis`.
4. **Р9** — Stampede срабатывает по перезарядке без врагов рядом.

Ранги проверяются на Kez (у Dragonus врождённая даёт `TargetCount` +1, это проверяется отдельно для Annihilation и Track). Ожидания — из данных (`RotTests.Base`) и таблицы рангов requirements.md.
- Реестр: `Run.IsImplemented` истинно, обработчик нужного типа, нет диагностик `ability:*` и `damage-type:*`; тип урона физический.
- Ранги 1, 2, 3, 9 — по таблице.

- Инструменты: `Tools/tests/test_audit.py` — новые классы фабрики и Annihilation implemented; `python3 -m unittest discover -s Tools/tests`.
- Unity: обычный smoke и `Tools/mac-smoke.sh -thornForce=swashbuckle,stampede,annihilation,track`; EditMode `SmokeForceTests.AllHitWaitsForEveryForcedKey`.

## Риски
- Предложение четырёх новых способностей при уровне меняет выбор улучшений у забегов с прежними seed (как в Task 19, 21, 22); тесты, зависящие от точного выбора, уже не опираются на него.
- Вынос `RectangleTargets` трогает Echo Strike; защищён `EchoStrikeTests` без изменения ожиданий.
- Stampede делает героя неуязвимым на 3.5–5.5 с из 30: бот-забеги могут жить дольше. Тесты на смерть героя используют `DisableAbilities`.
- Р20 (а) заметно добавляет золота; валюта пока не записывается в профиль (Task 31), баланс — блок E.
